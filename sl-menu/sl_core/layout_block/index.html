    Layout Blocks

    Create an unlimited number of custom layout blocks, place them anywhere on your website pages, and display any content or OpenCart modules in these positions.

    Features

    • Create an unlimited number of layout blocks with a structure of up to 4 columns.
    • Display blocks anywhere on the website. Placement from the admin panel is limited only by the available templates and their elements (HTML tags).
    • Configure individual column widths for desktop, tablet, and mobile devices.
    • Assign any module to any column of a created block and layout.

    Listing

    The page with a list of all created blocks is available via the menu link, if enabled, or via the link on the extension configuration page. It consists of:

    1. A table listing the created blocks
    2. Custom configuration of displayed columns
    3. Block list filtering

    Adding a New Block

    Example

    As an example, we will add a block for displaying an information module above the website header on the home page.

    We will create the module itself and add it to this block later in the last section of the documentation.

    To open the page for creating a new block, click the [ Add ] button.

    A page consisting of two tabs will open:

    1. Main block configuration, its appearance, and placement
    2. Filling the block with website modules

    Configuration

    At this step, fill in the form fields.

    Name - the field can contain arbitrary text and is only required for convenient searching and identification of the block in the list.

    Template Search

    Template - an autocomplete field. Start entering the path (route) of the required template and select the desired one from the list.

    Example

    Select common/header, as it is responsible for the website header, and the new block will be added relative to it.

    The following basic concepts are important for a better understanding:

    1. Each website page consists of separate blocks representing a rendered HTML template.
    2. A template can display either a large part of a page or a very small one.
    3. Nesting smaller templates within larger ones forms the final appearance of the page.
    4. Each template, including templates of third-party themes, has its own path (route), which allows new blocks with modules to be inserted into its markup.

    Placement Relative to the Template

    Placement - the field determines how the new block will be displayed relative to the template.

    • Before template
    • After template

    Accordingly, the new block will be displayed before or after all template content.

    Example

    Neither option is suitable because the common/header template, unlike the others, contains the beginning of the markup for each website page as a whole, including the root <html> tag, and simply adding a custom block by selecting before the template would be a bad idea. If after the template is selected, the new block will be displayed after the website header, namely immediately after the main menu, which is also not suitable for the given task.

    Placement Relative to an Element

    The following placement options allow you to choose a specific location for adding the block

    • Before tag
    • After tag
    • Replace tag

    Accordingly, place the block before or after the target tag, or completely replace it.

    When choosing this type of placement, a field will appear where you can visually select the target tag from the template content using your mouse. The selection does not change the template content itself, it only helps the extension get the element's coordinates within the file.

    Not every tag is available for selection, but only those, that have a defined start (opening tag) and end (closing tag) within this template. The entire "body" of the tag will become highlighted, defining it as the target element.

    By example

    Let's specify the target tag <nav>, by clicking on it with the left mouse button. In this case, the Before tag placement option is exactly what is needed to display information above the site header.

    At this step, the form should look as follows:

    The remaining placement options:

    • Manually

    To use this option, you need to know the key that the block will receive when it is created. The key can be specified manually, or the field can be left empty, in which case a number (block ID) will be added to the reserved key name prefix.

    If none of the placement options are suitable for any reason, then, knowing the key, you can manually insert it anywhere in the template using any convenient editor. Following Twig template syntax, you need to insert the variable output, for example: {{sl_block_7}} or {{sl_block_top_line}}

    Block Container and Columns

    A layout block is a reserved place for displaying modules, which can also be divided into columns, with modules displayed in each column.

    A single column is essentially just a container. Two or more columns are formed using Bootstrap classes, styles, and markup. At the same time, you can set an adaptive width for each column for different user screen sizes. To do this, you need to:

    1. Select the number of columns in the block
    2. Add a column configuration for a specific screen size
    3. Set the responsive column widths
    4. Click the [ Apply ] button

    Example

    One column is required to implement the task. This value is selected by default, so leave it as is.

    Container - by default, each block is wrapped in a tag with the Bootstrap container class, but due to additional spacing this is not always necessary, especially if the block is already displayed inside a similar container.

    Example

    Leave it as is - enabled. The block will occupy the space above the website header and will be centered on the page just like the website header itself. If the parameter is disabled, the block will occupy the full width of the page, i.e. all available space.

    Grid gutters - enabled by default. The parameter adds or removes spacing between columns when present.

    Status - enables or disables the display of the block on the website.

    Example

    Enable the display of the block on the website.

    To save the completed form, click the button in the upper-right part of the page:

    • [ Add ] when creating
    • [ Save ] when editing the block.

    The layout block will be saved and will appear in the list on the extension's main page.

    Adding Modules to a Layout Block

    To add modules to a layout block:

    1. Go to the corresponding tab
    2. Select the layout where the modules will be displayed
    3. Click the [ Add ] button

    A layout tab with an empty table listing the modules added to it will be created. After adding modules to the table, they will be displayed where the block itself is located.

    Example

    Adding a module to a layout block is described in detail in the last section of the documentation.

    To save the layout block configuration, click the button in the upper-right corner of the page:

    • [ Add ] when creating
    • [ Save ] when editing the block

    OCMOD Compatibility

    OCMOD (OpenCart Modification) is an OpenCart feature that allows third-party extensions to modify the contents of OpenCart files. This can lead to conflicts between extensions and errors in the website's operation, but it is nevertheless used by many developers.

    Such changes made by third-party extensions also affect the contents of templates referenced by layout blocks. In most cases, this should not affect the positioning of the layout block, but 100% compatibility with third-party extensions is not guaranteed.

    If a layout block references a template file affected by OCMOD, then changes to the layout block related to Placement and the Target Template Element will require the modifiers to be updated.

    Compatibility with the Native Theme Editor

    The functionality is located in the main OpenCart Design menu, under Theme Editor.

    The OpenCart Theme Editor allows you to modify template markup from the website admin panel. At the same time, the new contents of the file are saved in the database without modifying the file on the server.

    Warning

    Using this OpenCart functionality is not recommended because it completely ignores the operation of OpenCart's own OCMOD and any changes made to templates through events (events).

    If it turns out that a layout block references a template file affected by the Theme Editor, it is necessary to manually check that the block is displayed in the correct place in the template. The editor uses Twig syntax, and the block output will look like: {{ sl_block_ + block key }}

    A corresponding warning will be added inside the form when editing the layout block.
